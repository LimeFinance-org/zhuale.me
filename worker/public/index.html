03 · 数据边界

关于隐私

触发前，预设信息只以密文保存，解密密钥只在您的设备上。我们不会主动向任何机构提供触发前的可读内容；只有您主动触发后，协助流程才会收到您提交的信息。

触发前 · 平台可见

账户哈希、打卡周期、最近打卡时间

触发前 · 平台不可读

姓名、联系人、联系方式、备注

触发后 · 才会接收

仅处理您主动提交的协助信息

07 · 常见问题

疑问解答

我们如何盈利？

很简单，后期您如果被抓，我们律师会向您或您的紧急联系人收取律师费，如果您愿意，但这通常不会太高。

我们如何保证隐私？

敏感字段在浏览器端使用 AES-GCM 加密，解密密钥不会发送给服务端。服务端只保存密文与打卡所需元数据，因此触发前无法读取姓名、联系人等字段。

是否会被执法部门要求配合？

我们不会主动提供触发前的可读预设内容；由于服务端不持有解密密钥，平台在触发前也无法读取这些内容。触发后的信息只来自主动提交的触发请求；如遇适用法律要求，将按法律及正式程序处理。

紧急联系人会收到什么信息？

平台接收到您被抓后的预留信息后，安排专业对口的律师联系您预留的紧急联系人。

外部上报 API

支持两种请求方式，无需鉴权。推荐使用结构化请求；触发字段以明文写入服务端记录。

接口地址
https://www.zhuale.me/api/sos
GET请求示例（字段会出现在 URL 中）
https://www.zhuale.me/api/sos?name=张三&contact_name=李四&contact_method=13800000000&note=紧急求助
POSTJSON 示例
POST https://www.zhuale.me/api/sos Content-Type: application/json { "name": "张三", "contact_name": "李四", "contact_method": "13800000000", "note": "紧急求助" }
参数说明
- name: (必填) 您的姓名或代号 - contact_name: (必填) 紧急联系人姓名 - contact_method: (必填) 紧急联系人电话或联系方式 - note: (选填) 备注信息或求助内容
